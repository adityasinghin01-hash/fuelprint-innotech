## Write ordering and durable state

For a well-formed bounded request: authenticate and authorize actual capability/scope first; lookup(actor,scope,idempotency_key) and command UUID second; identical canonical body returns the same receipt before checking stale revisions; changed body or reused UUID conflicts409. A new request checks expected entity revision, scenario revision and all transition guards in one transaction. Thus retrying a successful approval after another change returns its original receipt; it does not approve the new state. Serialize actor-independent races in the sole writer.

Assign a persisted queue sequence. At a10Hz boundary, consume commands in that order before the two20Hz science steps, stamp their effective tick and commit resulting events/records/receipt updates atomically. Persist the ordered inputs/tick/output references required to replay through that committed tick, with restricted10simsecond checkpoints. Worker results cite previous_checkpoint_hash,base_tick,end_tick,input/config hashes; reject a stale base. After a stalled scheduler resumes, recheck host-monotonic freshness and neutralize before any new motion; never replay stale held velocity across a stall. SSE/outbox publishes after commit; a lost response is recovered from the receipt. A rejected transition has a durable reason without partial domain changes. If commands change a config while approval/capture is queued, the later command sees the new revision and rechecks eligibility.

Use host monotonic time for control expiry. At400ms since last accepted fresh input, target neutral by500ms; lease expires2s without eligible renewal. Control wall deadlines take priority over simulation batching/acceleration. Blocking numeric work runs off the control path, with bounded queue and process count1. Clock overload causes a durable pause/interruption when safe, not wall-time catch-up. On host loss no physical actuator is connected; the virtual world resumes stationary only after explicit reapproval.

Jobs persist input snapshot hash, exact refs, algorithm/model version, state, attempt_count, next retry, errors and outputs. Idempotent job key=(type,input hash,algorithm hash). Lease a job with owner/heartbeat; restart returns abandoned RUNNING jobs to pending only if pure recomputation of the same immutable inputs is valid. Three transient I/O **retries after the initial attempt** use1/2/4s+≤250ms jitter; numeric failures are recorded, not retried with relaxed settings. Export retries reuse the same sealed bytes/output identity. At the live2s analysis budget emit pending/budget-exceeded status with no recommendation; finish bounded offline if requested. No job writes the DB directly; it returns version-bound output to the authority.

## Snapshot, replay, disk and restart

A snapshot read starts a transaction, reads watermark and role-scoped projections together, then returns `{schema_version,run_ref,cursor,committed_tick,clock_epoch,scope,projection,health}`. Subscribe strictly after that cursor. Events carry cursor, aggregate ref, type, effective_tick and typed payload; global gaps may be authorized events outside scope. Ignore duplicates; do not treat a gap in globally filtered cursors as local data loss. If retention expired or buffered events exceed1000, discard partial projection and fetch a fresh snapshot. Reducer applies only monotonic per-aggregate revisions; initial read/update race is tested.1Hz polling may support read dashboards; it does not renew10Hz control. Loss of freshness disables mutations/movement until resync.

Blob order: create staging file on same filesystem; write/flush/fsync, compute hash/length, rename to content-addressed final path atomically, fsync parent; only then commit references/outbox in SQLite. Precommit orphan is quarantined on recovery; committed missing/corrupt blob blocks scientific reuse/export. Existing-hash files are length/hash checked before reuse. A DB row cannot make a file durable by declaration. Bound checkpoint files and perform disk-capacity checks before allocation. Backup pins prevent referenced-blob garbage collection; no automatic deletion of evidence.

Recover from last committed checkpoint/tick, verify referenced required blobs, restore deterministic states/RNG, then append restart interruption: active captures/missions INTERRUPTED, velocity neutral, leases revoked, affected approvals invalidated. Do not integrate elapsed downtime, manufacture volume or restart collection. Interrupted job outputs never attach to a changed input.
